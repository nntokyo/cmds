# 詰まりの通知：使う手順（1 枚）

ペインが許可の確認で止まったまま、預けた指示が届かないまま、あるいは作業を終えて手が空いたままになったときに、
決めた 1 つのペイン（指示を配るペイン）へ 1 行で知らせる機能です。全ペインを見て回らなくても、動けるペインと
止まっているペインが分かります。英語の説明は [queue.md](queue.md#stalled-panes) にあります。この機能が入った版の
cmds で使えます（`cmds stall` が動けば入っています）。既定は切です。

## 入れる（1 行）

知らせを受けるペインの中で、次の 1 行を実行します。

```sh
cmds stall notice on --to "$CMDS_PANE_ID"
```

- 別のペインに知らせるときは、`--to p12` のようにペインの番号を書きます（番号は `cmds ls` で見られます）。
- 分数を変えるとき：`cmds stall notice --input-minutes 5 --queue-minutes 20 --idle-minutes 30`（既定は、入力待ち
  10 分、未達 15 分、待機 10 分。1〜1440 分）。
- 待機の通知だけ止めるとき：`cmds stall notice --idle-minutes 0`。
- 設定は cmds を開き直しても残ります。知らせ先のペインは、開き直した後も同じペインです。

## 届く 1 行

```
cmds 詰まり通知: ペイン p7 / 入力待ち / 12 分 / 理由 permission-or-question
cmds 詰まり通知: ペイン p9 / 預けた指示が未達 / 15 分 / 理由 typed-input
cmds 詰まり通知: ペイン p5 / 待機中 / 10 分 / 理由 idle
```

- 形はいつも同じで、ペインの番号・状態・分数・理由の語だけです。ペインの画面の文字は入りません。
- 同じ詰まりが続いている間は、1 時間ごとにもう 1 行届きます。解けたら止まります。
- この 1 行は `cmds queue add` と同じ預かりで届きます。知らせ先のペインが作業中の間は、手が空くまで待ちます。
- cmds は、止まっているペインには何も入力しません。許可の確認にも答えません。ウィンドウも前に出しません。
  どうするかは、知らせを受けた側が決めます。

## 理由の語（10）

| 語 | 意味 | まず見るもの |
|---|---|---|
| `idle` | agent が作業を終え、入力欄で待っている。実行中のものも、質問も無い（状態は「待機中」） | 次の仕事を渡す。渡すものが無ければそのまま |
| `permission-or-question` | agent が許可の確認か質問を出して、答えを待っている（状態は「入力待ち」） | そのペインの画面。答えるのは人 |
| `needs-input` | 預けた指示が、agent の許可の確認・質問・選択の画面のために入力できない | 同上 |
| `typed-input` | 入力欄に、人が打った文字が残っている | 入力欄。送るか消すかは、打った人が決める |
| `busy` | agent が作業を続けていて、指示を入力する切れ目がない | 長い作業か、止まっていないか |
| `no-agent` | ペインに agent がいない（シェルに戻っている） | agent を起動し直すか、指示を取り消す |
| `other-program` | 別のプログラムが前面で動いている（または agent の種類が分からない） | そのプログラムの終了を待つか、取り消す |
| `other-input` | 予定の実行・アカウントの切り替え・再開が、そのペインを使っている | ふつうは数分で解ける。続くなら予定の履歴 |
| `pane-closed` | 指示を預けたペインが、いま開いていない（ペインの番号は `-`） | `cmds queue list` で確かめ、取り消す |
| `unknown` | cmds が理由をまだ記録していない（入力を試している途中など） | `cmds queue list` で理由を見直す |

## いまの状態を見る

```sh
cmds stall          # 通知の入切、知らせ先、いま詰まっているペインの一覧（通知が切でも見られます）
cmds queue list     # 預けた指示と、届いていない理由
```

## 知らせ先が作業中のとき（ファイル）

通知の 1 行は、知らせ先のペインの手が空くまで待ちます。その間も読めるように、通知が入の間は、同じ内容を 1 分ごとに
ファイルへ書き出します。場所は `cmds stall` の `file` の行に出ます（ふつうは
`~/Library/Application Support/cmds/stalls.txt`）。

```
cmds stall 2026-11-26T08:12:00Z 2
cmds 詰まり通知: ペイン p7 / 入力待ち / 12 分 / 理由 permission-or-question
cmds 詰まり通知: ペイン p9 / 預けた指示が未達 / 15 分 / 理由 typed-input
```

1 行目は、書いた時刻（UTC）と件数です。詰まりが無いときも書き直すので、時刻が 2 分以上古ければ、cmds が動いて
いないか、通知が切です。通知を切ると、このファイルは消えます。`cat` で読むだけでよく、cmds には何も送りません。

## 切る

```sh
cmds stall notice off
```

知らせ先と分数の設定は残り、`cmds stall notice on` だけでまた入ります。すでに預かりに入っている通知の行は、
`cmds queue list` で番号を見て `cmds queue cancel <番号>` で取り消せます。

## 知っておくこと

- 入力待ちと待機の分数は、agent が最後に作業していた時点から数えます。agent のいないペイン（シェルだけ）は、
  待機としては知らせません。
- 手が空いたままのペインは、1 時間ごとにもう 1 行届きます。夜間など、空いていてよい時間は
  `--idle-minutes 0` で待機の通知だけ止められます。
- agent が cmds に知らせない画面（起動時のフォルダの信頼確認など）は、「入力待ち」としては分かりません。そのペインに
  預けた指示があるときだけ、「預けた指示が未達」として届きます。
- 知らせ先のペイン自身の詰まりは、知らせません。
